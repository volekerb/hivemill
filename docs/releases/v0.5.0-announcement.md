# What's new in Hivemill v0.5.0

Hivemill v0.5.0 is a pre-release. It starts a Go rewrite of the factory's own tools, makes herdr-core the default terminal backend, adds a dashboard for the Herdr desktop app and a worker sandbox, and lets you run Cursor beside Claude. This page sums up what changed for you; the [CHANGELOG](../../CHANGELOG.md) has every detail.

## Where you run and watch it

| Surface | What it is | Status in v0.5.0 |
|---|---|---|
| herdr-core (`hc`) | The headless core of herdr. Hivemill runs its agent panes through it. | The default backend: `terminal_backend = auto` prefers `hc` when both binaries are installed. See [terminal backends](https://github.com/volekerb/hivemill/blob/main/docs/terminal-backends.md). |
| Classic herdr terminal UI | The herdr TUI you attach to and watch panes in. | Still supported, opt-in: set `terminal_backend = herdr`. |
| Herdr desktop app plugin | The Hivemill dashboard: a status bar and a dashboard tab in the Herdr desktop app, installed with `/hivemill:setup`. | Available. |
| Web view | `factory serve`: the web UI with goals, agents, cost and throughput. | Available. |

## What changed

- **A Go rewrite, opt-in.** The worker-guard hook now has a Go build. In the measured table, a call takes about 8 ms in Go and about 69 ms in Python, about 8.5x to 9x. A large part of the `factory` command also runs in Go. Python stays the default. The default guard, the default command, the tick and the web UI all still run in Python.
- **herdr-core is the default backend.** `terminal_backend = auto` now prefers `hc` when both binaries are installed. The classic herdr terminal UI still works: set `terminal_backend = herdr`.
- **A worker sandbox.** It hides the owner's logins from a worker. It is opt-in and off by default, and it works on Linux only. It is not a full security boundary. The 24-hour verification of the coder step is still running.
- **Cursor beside Claude.** Claude is still the default. You can pick Cursor for single roles.
- **A fast lane for pull requests.** The merge step skips runs it does not need, such as the guard corpus on a push that does not touch it.
- **A Hivemill dashboard in the Herdr desktop app.** A status bar and a dashboard tab. The setup skill offers to install them.
- **Scheduled jobs.** Define up to five recurring jobs with `factory schedule`. Each one has its own goal and a token cap per run.

## Known limits

This is a pre-release, so interfaces may change before 1.0. Go is opt-in, and the sandbox is opt-in and not a full boundary. The Herdr app dashboard installs on the machine where the app runs, and the app must be set up there first. Hivemill runs on one Linux machine.

## Upgrade

Installs that have both `herdr` and `hc` switch to `hc` on upgrade, because `terminal_backend = auto` now prefers `hc`. Set `terminal_backend = herdr` to keep the old behaviour. A live factory needs no checkout: within a minute, the tick fast-forwards main in `~/factory` to the tag commit. Use `git checkout v0.5.0` only for a fresh install that is not live yet. Then run any `factory` command once so the database migration runs, and run `factory flags` to review the new settings. Every Go path stays off until you turn it on. The full steps are in the Upgrade section of the [CHANGELOG](../../CHANGELOG.md).
