# What's new in Hivemill v0.5.0

Hivemill v0.5.0 is a pre-release. It starts a Go rewrite of the factory's own tools, adds a first herdr-core pilot and a worker sandbox, and lets you run Cursor beside Claude. This page sums up what changed for you; the [CHANGELOG](../../CHANGELOG.md) has every detail.

## What changed

- **A Go rewrite, opt-in.** The worker-guard hook now has a Go build. In the measured table, a call takes about 8 ms in Go and about 69 ms in Python, about 8.5x to 9x. A large part of the `factory` command also runs in Go. Python stays the default. The default guard, the default command, the tick and the web UI all still run in Python.
- **A herdr-core pilot.** One worker runs on the herdr-core backend. Everything else stays on herdr, and the default does not change.
- **A worker sandbox.** It hides the owner's logins from a worker. It is opt-in and off by default, and it works on Linux only. It is not a full security boundary. The 24-hour verification of the coder step is still running.
- **Cursor beside Claude.** Claude is still the default. You can pick Cursor for single roles.
- **A fast lane for pull requests.** The merge step skips runs it does not need, such as the guard corpus on a push that does not touch it.
- **Scheduled jobs.** Define up to five recurring jobs with `factory schedule`. Each one has its own goal and a token cap per run.

## Known limits

This is a pre-release, so interfaces may change before 1.0. Go is opt-in, the herdr-core pilot has one worker, and the sandbox is opt-in and not a full boundary. A Hivemill dashboard in the Herdr desktop app is coming next. The setup skill does not yet install the Herdr app views. Hivemill runs on one Linux machine.

## Upgrade

A live factory needs no checkout: within a minute, the tick fast-forwards main in `~/factory` to the tag commit. Use `git checkout v0.5.0` only for a fresh install that is not live yet. Then run any `factory` command once so the database migration runs, and run `factory flags` to review the new settings. Every Go path stays off until you turn it on. The full steps are in the Upgrade section of the [CHANGELOG](../../CHANGELOG.md).
