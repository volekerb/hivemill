## Post

```text
My AI coding factory got faster, safer and a little less tied to one vendor.

Hivemill v0.5.0 is the release you can open below. What changed:

- A Go worker guard: the hook that checks every worker command takes about 8 ms instead of about 69 ms in Python, roughly 8.5x to 9x on the hook. Python is still the default.
- A herdr-core pilot: one of my workers now runs on herdr-core, while herdr stays the default terminal for everyone else.
- A worker sandbox, opt-in: it keeps a worker's credentials apart from mine.
- Claude and Cursor agents side by side, each as a full team in one factory.
- Scheduled jobs: recurring jobs that I define once and the factory runs on its own.

About the sandbox: it isolates worker credentials. A worker gets its own login and a per-role GitHub token, not my logins or keys. On Linux each worker runs in an unprivileged user and mount namespace that sees only an allow-list view of the home directory. It is opt-in, and its verification is still running, so I do not call it a full security boundary yet.

About herdr-core: it is the headless core (the hc command) of the herdr terminal multiplexer. I use it as a second terminal backend that I can switch on for a single worker. The next step is a Hivemill dashboard inside the Herdr desktop app, coming next. It is a status bar plus a dashboard tab with alerts, budget and cost, resources per machine, and the factory itself: lanes, what needs me, active goals and agents. The idea is to manage the whole factory without leaving the app I work in.

The short film attached to this post is a captioned walk-through of the factory, not a screen recording. The release notes and the full list of changes are here:
https://github.com/volekerb/hivemill/releases/tag/v0.5.0
```
