# Scout risk classifier: Bash scopes that count as open

A `Bash(<cmd>:…)` scope is treated like bare `Bash` (flagged `shell-in-markdown,network`) when its command word, after quotes and backslashes are removed, is a shell, interpreter, wrapper or launcher (`ssh`, `scp`, `rsync`, `busybox`, `chroot`, `unshare`, `nsenter`, `script`, `expect`, `tclsh`, `lua`, `R`, `Rscript`, `julia` and the earlier list), or when it starts with an env assignment (`FOO=1 sh`). `git` stays scoped only for the read-only subcommands `status`, `log`, `diff`, `show`, `rev-parse`, `ls-files`, `blame` with no option or shell metacharacter in the scope; every other git form (`git grep`, `git -c`, `git rebase`, `git bisect run`, `git submodule foreach`) and all of `make` is open. A command word that contains expansion, globbing or brace characters (`$ ` [ ] { } ~ * ? ( )`, checked before and after quote stripping) is open, because the shell resolves it to an unknown command (`$'\x73h'`, `$SHELL`, `s[h]`, `{sh,}`). For the allowed git subcommands the text after the colon is checked like the words before it: only a bare `*` is accepted, so `Bash(git log:--output=x)` is open. The command word is also allow-listed: both its raw and its quote-stripped form must consist only of `A-Z a-z 0-9 . _ / + -`, so zsh `=sh`, `!`, `{`, `[[`, `@` and any other shell syntax is open, and a newline anywhere in the scope is open. Shell keywords and precommand words are open when they are the command word, because the real command is the next word: `time noglob nocorrect builtin command exec coproc if then while until for case select function eval source . nohup env sudo doas - !`. The classifier fails closed: the sandbox is the boundary, this only decides what may be auto-evaluated.

# Scout risk classifier: MCP set up through text

`mcp` is set not only for `.mcp.json` and an `mcpServers` key in `plugin.json`, but also when a scanned `plugin.json`, `SKILL.md`, command or agent file (a) contains `mcp add` (`claude mcp add`, `mcp add --transport http`, `mcp add-json`, `mcp add-from-claude-desktop`), (b) contains the text `mcpServers`, or (c) names an `http(s)` URL whose host, path or query contains `mcp` (case-insensitive), e.g. `https://mcp.asana.com/v2/mcp`. A remote MCP endpoint URL also sets `network`, because the plugin talks to a hosted service. Prose that only says "MCP" (no `mcp add`, no `mcpServers`, no such URL) stays `prompt-only`; the trade-off is that any URL with `mcp` in its host or path is flagged, even when it is only documentation. `README.md` is not read (only `plugin.json`, `SKILL.md`, `commands/` and `agents/` files).

Why C-0022 (asana) was rated `prompt-only`: it has no `.mcp.json` and no `mcpServers` key; `shell-in-markdown` matches only `!`-backtick lines or a fenced block opened with `` ```! `` (a block the harness runs), not a `` ```bash `` block that tells the user to run `claude mcp add`; `network` matched only `curl`/`wget`/`WebFetch` or "fetch/download … https://", and the setup file has none of those, so its URLs and OAuth steps were not seen. The `bash` fence is user-run instruction text, not auto-run, so `shell-in-markdown` is left as is; the gap is closed by the `mcp` and `network` flags above.
