# Scout risk classifier: Bash scopes that count as open

A `Bash(<cmd>:…)` scope is treated like bare `Bash` (flagged `shell-in-markdown,network`) when its command word, after quotes and backslashes are removed, is a shell, interpreter, wrapper or launcher (`ssh`, `scp`, `rsync`, `busybox`, `chroot`, `unshare`, `nsenter`, `script`, `expect`, `tclsh`, `lua`, `R`, `Rscript`, `julia` and the earlier list), or when it starts with an env assignment (`FOO=1 sh`). `git` stays scoped only for the read-only subcommands `status`, `log`, `diff`, `show`, `rev-parse`, `ls-files`, `blame` with no option or shell metacharacter in the scope; every other git form (`git grep`, `git -c`, `git rebase`, `git bisect run`, `git submodule foreach`) and all of `make` is open. A command word that contains expansion, globbing or brace characters (`$ ` [ ] { } ~ * ? ( )`, checked before and after quote stripping) is open, because the shell resolves it to an unknown command (`$'\x73h'`, `$SHELL`, `s[h]`, `{sh,}`). For the allowed git subcommands the text after the colon is checked like the words before it: only a bare `*` is accepted, so `Bash(git log:--output=x)` is open. The command word is also allow-listed: both its raw and its quote-stripped form must consist only of `A-Z a-z 0-9 . _ / + -`, so zsh `=sh`, `!`, `{`, `[[`, `@` and any other shell syntax is open, and a newline anywhere in the scope is open. Shell keywords and precommand words are open when they are the command word, because the real command is the next word: `time noglob nocorrect builtin command exec coproc if then while until for case select function eval source . nohup env sudo doas - !`. The classifier fails closed: the sandbox is the boundary, this only decides what may be auto-evaluated.

# Scout risk classifier: MCP set up through text

`mcp` is set not only for `.mcp.json` and an `mcpServers` key in `plugin.json`, but also when a scanned `plugin.json`, `SKILL.md`, command or agent file (a) contains `mcp add` (`claude mcp add`, `mcp add --transport http`, `mcp add-json`, `mcp add-from-claude-desktop`), (b) contains the text `mcpServers`, or (c) names an `http(s)` URL whose host, path or query contains `mcp` (case-insensitive), e.g. `https://mcp.asana.com/v2/mcp`. A remote MCP endpoint URL also sets `network`, because the plugin talks to a hosted service. Prose that only says "MCP" (no `mcp add`, no `mcpServers`, no such URL) stays `prompt-only`; the trade-off is that any URL with `mcp` in its host or path is flagged, even when it is only documentation. `README.md` (up to 3 per candidate) is read for MCP setup text only (`mcp`/`network`); it never sets `shell-in-markdown`, so a README that mentions `curl` stays `prompt-only`.

Why C-0022 (asana) was rated `prompt-only`: it has no `.mcp.json` and no `mcpServers` key; `shell-in-markdown` matches only `!`-backtick lines or a fenced block opened with `` ```! `` (a block the harness runs), not a `` ```bash `` block that tells the user to run `claude mcp add`; `network` matched only `curl`/`wget`/`WebFetch` or "fetch/download … https://", and the setup file has none of those, so its URLs and OAuth steps were not seen. The `bash` fence is user-run instruction text, not auto-run, so `shell-in-markdown` is left as is; the gap is closed by the `mcp` and `network` flags above.

# Scout risk classifier: residual MCP gaps and the `scripts` flag (T-0377)

MCP text matching also handles: shell line continuations (`claude mcp \<newline> add`), JSON-escaped slashes (`https:\/\/mcp.example\/x`), a `)` inside a URL path, and launchers `npx|bunx|uvx|pipx run|pnpm dlx|npm exec|yarn dlx` followed within 200 characters on the same line (a bounded scan, linear on a 64 KiB blob) by a package containing `mcp` or `modelcontextprotocol` (`npx -y mcp-remote <url>`); a launcher match sets `mcp` and `network` (it downloads and runs a package). `mcp__*` tool names in `allowed-tools`/`tools` frontmatter set `mcp`. A `plugin.json` with `mcpServers` and any `http(s)` URL also sets `network`, even when the URL has no `mcp` in it. Prose that only names a tool such as `mcp__x` outside frontmatter stays `prompt-only`.

`scripts` is decided by real executability, not by "not markdown". A blob is `scripts` when its mode is `100755`, its extension is a script or binary type (`.sh .bash .zsh .py .js .cjs .mjs .ts .rb .pl .ps1 .bat .cmd .exe .bin .so .dylib .jar .wasm` and similar, see `SCRIPT_EXT`), or its name is `package.json`/`Makefile`/`Dockerfile`-like (build files that run code), or it has no recognised type and starts with `#!`. Inert data is not `scripts`: images, fonts, `.svg`, `.gitignore`/`.gitattributes`, licence/readme files, `.txt .csv .md`, and `.json/.yaml/.toml/.ini` that are not hooks or MCP configs. A file of an unrecognised type without a shebang (or unreadable, or past 10 sniffed blobs) is flagged `unknown`, never dropped. `.mcp.example.json` (any `.mcp.*.json`) is flagged `mcp`: the harness does not load it, but it declares servers a user would copy in, so a fail-closed rating keeps it visible. Other `.json/.yaml/.toml` files are read (up to 10) and flagged `hooks` (a `hooks` key or `[hooks]` table), `mcp` (MCP text as above) by content; unreadable ones are `unknown`. Well-known code-running configs (`tasks.json`, `devcontainer.json`, `composer.json`, `pyproject.toml`, `settings*.json`, `lefthook.yml`, `.pre-commit-config.yaml`) are `scripts`. A config that names a command to start is `scripts`, never `prompt-only`: `.lsp.json`, a `lspServers` key (also inline in `plugin.json`), or any `"command":` / `command =` entry (`.vscode/mcp.json`, Codex `config.toml` `[mcp_servers.*]`); `mcp_servers` also counts as MCP text, and an `*mcp*.json` with a command is flagged `mcp`. A `README.md` under `commands/` or `agents/` is still read as a command/agent file.

Config command-key detection: a `.json/.jsonc/.json5` config that parses is checked by its decoded keys (every dict key, including dicts inside lists, walked iteratively), so `"\u0063ommand"` counts as `command`; `command` and `lspServers` set `scripts`, `hooks` sets `hooks`, `mcpServers`/`mcp_servers` set `mcp`. A config that does not parse (jsonc comments, json5, broken) is scanned as text with `\uXXXX` escapes decoded. toml configs flag `command` as a key at line start or inside an inline table (`{ command = "npx" }`), bare or quoted. yaml configs flag `command:` as a mapping key in block style, as a `- ` list item key, or in flow style (`{command: npx}`), bare or quoted. The word "command" in a value, or a key such as `commands`, stays `prompt-only`. All patterns are linear, so a 64 KiB hostile config classifies in well under a second.
