# Goal lifecycle

The pm owns a goal's tickets end to end, but never writes code or git, merges or records verdicts.
- **Audit.** When every build task is done or cancelled, the lead creates an audit pm task and spawns the pm. The pm checks each task against its acceptance list and each success criterion against evidence, then records `factory goal audit G --ready|--gaps --report -`. At most 2 audit rounds; a third goes to the director.
- **Follow-up.** For a gap in merged work: `factory task add … --follow-up-of T-x` (the parent must be a done task of the same goal). Merged (PR) tasks are never reopened.
- **Reopen.** `factory task reopen T --reason TEXT` sends a done task without a PR back to `todo` (pm in its own goal, lead, director, owner). A pm marks a task done only for a non-coder task without a PR, with `--note`; a coder-role task without a PR is closed only by the lead, director or owner.
- **Sign-off.** `factory goal signoff G --audit N --reason TEXT`: director (or owner) only, never a worker process, on the latest `ready` audit.
- **Close.** `factory goal close G --reason TEXT` (pm of the goal, director or owner) needs a ready audit, a sign-off for it, and every task done or cancelled and unchanged since the sign-off (exit 4 otherwise). The old status-to-done shortcut is refused except for the owner, whose override is logged as `owner-override-close`.
- **Reopen a goal.** `factory goal status G active --note TEXT`: director or owner only.

## Goal token tally (`factory goal tokens`)
`factory goal tokens G` prints a goal's Claude token tally from the `goal_token_tally` table. It reads that table only and never opens a log, so a spawn path can call it at no cost. The tally is `input + output + cache_write_5m + cache_write_1h`; `cache_read` is printed apart and is not in it. Sessions that cannot be tied to a goal are shown on one line, "not counted in any goal", so a goal never looks cheaper than it is. No table rows yet prints "no tally yet" (exit 0). A Cursor-org goal prints that Cursor reports agent-hours and no tokens.

The tick fills the table when config `goal_token_tally_s` is above 0 (default 0 = off, nothing is read). Each pass, started at most every `goal_token_tally_s` seconds, drains one fresh `TokenIndex` (refresh until a refresh reads 0 bytes), computes the by-goal figures like `/tokens` (`web/tokens.py` `attribute` + `rollup`) and replaces all rows in one transaction. The pass stops after 60 s between refreshes: nothing is stored then, the old rows stay and one failure event (`goal-token-tally-failed`, throttled to one per hour) is logged, because a partial figure would be an undercount. The attempt time is kept for success and failure alike, so a failing pass is not retried every tick. It only reports; it refuses nothing.

## Goal token limit (`factory goal edit G --token-limit N`)
A goal can carry a token limit (`goals.token_limit`, NULL = none). Only the director, boss or owner may set it (a lead or worker gets exit 3: a lead that raises its own limit would defeat it); `0` clears it, a negative number is refused (exit 2). `factory goal show` prints the limit next to the tally from `factory goal tokens` when one is set.

The tick step right after the tally warns once: when a Claude-org goal's cached tally reaches 80% of its limit, the goal's lead and its org's director each get one alert (kind `alert`, sender `tick`); a goal without a lead gets the director's one message only. The throttle key `goal-token-warn:<goal>:<limit>` holds goal and limit, so a new limit arms the warning again. The text holds only goal id, tally, limit and percent, never the goal title. Goals without a limit cost one query; Cursor-org goals are never warned (Cursor reports agent-hours). A failure logs one throttled event (`goal-token-warn-failed`) and never breaks the tick. The warning itself refuses nothing. The refusal is in `spawn()` (`goal_token_gate`, using `goal_token_refusal`): once the cached tally of a Claude-org goal is at or above its limit, a `coder` or `pm` spawn on that goal is refused with exit 3 and nothing is started. The message is `factory: <goal> is at its token limit: tally <used> tokens, limit <limit>. A <role> is new work and is not started; judge, reviewer, qa, lead and cleaner still are. To go on, the director or owner raises it: factory goal edit <goal> --token-limit N`. Other roles (judge, reviewer, qa, lead, cleaner) still start. The check fails open: no limit, no tally row yet, or a Cursor-org goal means no refusal. A queued spawn is cancelled once and the lead is told; a lead-less dispatch is skipped with one alert per task.
