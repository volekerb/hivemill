# Updating persistent agents

Workers (pm, coder, qa, reviewer, judge, cleaner) read `roles/` when they are spawned, so a role change reaches them at their next spawn. Persistent agents (boss, director, leads) keep running, so they are restarted with `--resume`: the conversation is kept and the new role text is read.

1. A merge that touches `roles/` (`_common.md`, `<role>.md`, `settings/<role>.json.in`, `hooks/`, `plugins/<role>/`) makes the judge hook send a "role files changed: relaunch pending" request to each affected live agent, and the director a list of `factory relaunch <name> --when-idle` commands (the boss too when the director is affected).
2. The director runs `factory relaunch <name> --when-idle` (the boss may do this for the director only; the director may do it for itself). This only sets `relaunch_requested_at/by` on the agent; `factory agents` shows RELAUNCH-PENDING.
3. The tick, after it has exported state (so the main checkout holds the merged role files), looks at each flagged live agent. While it is working, blocked or not listed, nothing happens. When it is idle, the tick checks the spawn gate with the agent's own slot discounted (every cap still applies: live agents, claude processes, memory floor, usage limits). If the gate would refuse, the pane is not closed: the request stays and is retried next tick (event `relaunch-deferred`, at most hourly). Otherwise it clears the flag, records `relaunch-run`, closes the pane and starts the agent with `--resume <same session id>`, `--settings`, `--append-system-prompt-file run/<name>.prompt.md`, `--plugin-dir` and `--system-prompt-snapshot off`. A failure records `relaunch-failed` and sends one alert to the requester.
4. `--system-prompt-snapshot off` is passed on every resume start (`relaunch`, the tick, `up`): without it Claude Code reuses the system prompt recorded at the first request. Fresh spawns do not pass it. A resumed agent reads `run/<name>.prompt.md` on every request, so that file is only rewritten right before the same agent's own (re)launch and never deleted.

Assumption: herdr's own restore does not resume agents (`resume_agents_on_restore=false`). A bare `claude --resume` started by herdr would reuse the stale recorded prompt; such an agent is caught by flagless detection, and `factory relaunch <name>` repairs it.

`factory relaunch <name>` without `--when-idle` restarts at once (owner or director; boss for the director). It refuses a director relaunching itself (exit 3, use `--when-idle`) and an agent that is mid-turn (exit 2, `--force` overrides). `--dry-run` prints the plan.
