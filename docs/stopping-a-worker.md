# Stopping a worker

`factory stop <agent> [--reason TEXT] [--now] [--dry-run]` (owner; director for any worker; lead for its own team's workers; never boss/director/lead targets, never run by a worker) is a real STOP for a busy worker. It sends a `decision` message `STOP` (the worker must read it with `factory inbox` before `factory done` works), records `stop-requested` and sets `agents.stop_requested_at`, then presses Esc in the worker's pane, waits up to 30 s for it to settle and nudges it to read its inbox. `--dry-run` prints the steps and changes nothing. If the worker is still live after config `stop_timeout_s` (default `300`), the tick runs the hard fallback: it closes the pane and sets status `stopped` (which frees the gate slot) only when herdr no longer lists the pane AND no claude process runs the session; otherwise the agent stays `live` (still counted), a `stop-failed` event is recorded (`close-failed`, `process-alive` or `process-unknown`: no session id from the row or from herdr, or an unreadable /proc, fails closed and keeps the agent live; the message says whether the pane was NOT closed or was closed with the process state unknown, and that the retry will not succeed on its own: end it by hand or relaunch it), the caller (also for `--now`) gets one message per failure kind and the tick retries at most once per `stop_timeout_s`. `--now` skips Esc/wait/nudge and runs the fallback at once. A `stopped` agent is protected like `done` by `factory clean` and listed by `factory agents --all`. A worker that runs `factory done` after a stop clears the flag; `factory done` is refused (exit 2) for an agent that is not `live`, so a `lost` persistent role must be relaunched, not done. A repeat `factory stop` on an agent that is already stopping changes nothing and prints the next fallback time: the later of the request and the last attempt plus `stop_timeout_s`, with `(retrying; last attempt <ts>)` once an attempt failed. A repeat `factory stop --now` on an already-stopping agent escalates instead: it records `stop-escalated`, sends no new STOP message, keeps the original `stop_requested_at`, and runs the hard fallback at once with the same close and process checks, output and exit codes as `--now` (if the tick attempted the fallback at the same moment, it prints that nothing was closed and exits 0); with `--dry-run` it prints that plan and changes nothing. Messages about a force-stop or a failed stop tell the lead to check `gh pr list --head <branch>` and `factory task show <task>` before reassigning.
